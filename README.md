# SpeakReady

SpeakReady עוזר לתלמידים לתרגל תשובות באנגלית לקראת הבגרות בעל פה.
גרסת הפיילוט כוללת תרגול עצמאי: בחירת שאלה, הקלטה, האזנה לפני שליחה,
תמלול ומשוב AI, היסטוריית ניסיונות ומחיקה.

## מה ממומש

- הרשמה וכניסה עם BCrypt, סשן שרת ועוגייה מוצפנת מסוג HttpOnly ששורדת רענון (8 שעות).
- אימות בכל בקשת API, הרשאות מנהל ובדיקת בעלות על כל ניסיון והקלטה.
- שלושה תרגילים אמיתיים ב־MySQL: הצגה עצמית, חוויה מהעבר והבעת דעה.
- הקלטה בדפדפן עד 120 שניות, האזנה והקלטה מחדש לפני שליחה.
- אחסון שמע פרטי, בדיקת תוכן ומשך הקובץ בשרת באמצעות FFmpeg/ffprobe.
- תור ניתוח ב־MySQL, תמלול ומשוב OpenAI, זיהוי שקט, טיפול בכשל ושני ניסיונות חוזרים.
- מכסה ברירת מחדל של חמישה ניתוחים ביום לתלמיד; ניסיון חוזר נכלל במכסה ומחיקה אינה מאפסת אותה.
- משוב על תוכן, דקדוק ואוצר מילים בלבד. אין הערכת הגייה, שטף או ציון בגרות.
- היסטוריה של 100 הניסיונות האחרונים, השמעה ומחיקת הקלטה/תמלול/משוב.

מסכי המורה והמנהל של שלב 9 נשמרו בקוד ללא נתיבי גלישה. הם אינם מוצגים כיכולות פעילות בפיילוט.

## מבנה

| שכבה | אחריות |
|---|---|
| Model | ישויות, DTOs וכללי ולידציה משותפים |
| DAL | שאילתות MySQL, חשבונות וסשנים, תוכן, תור עבודה ומכסות |
| API | אימות והרשאות, העלאת שמע פרטית ועיבוד AI ברקע |
| View | Blazor Server בעברית, הקלטה בדפדפן וממשק תלמיד |

הדפדפן ניגש לאתר בלבד. האתר מעביר ל־API אסימון נפרד לכל משתמש; הוא אינו נשמר ב־localStorage או נחשף ל־JavaScript.

## הפעלה מקומית

נדרשים .NET SDK 10, ‏MySQL 8 ו־FFmpeg (`ffmpeg` ו־`ffprobe` זמינים ב־PATH).

1. פתחו את `SpeakReady.sln` ב־Visual Studio, או השתמשו בפקודות הבאות משורש המאגר.
2. הגדירו ב־API את `ConnectionStrings:DefaultConnection` באמצעות **Manage User Secrets**. לדוגמה, עם פרטי החיבור שלכם:

   ```sh
   dotnet user-secrets set --project API 'ConnectionStrings:DefaultConnection' 'Server=localhost;User ID=speakready;Password=YOUR_PASSWORD;SslMode=Required'
   ```

   המשתמש צריך הרשאות על `SpeakReadyDB`, כולל יצירת טבלאות. האתחול יוצר את בסיס הנתונים אם צריך.
3. למשוב אמיתי הגדירו את `OpenAI:ApiKey` ב־User Secrets של API. אין להכניס מפתח ל־Git.
   ללא מפתח אפשר להירשם, לבחור תרגיל ולהקליט מקומית; השליחה תחזיר הודעה שהשירות לא הוגדר.
4. הפעילו בשני מסופים:

   ```sh
   dotnet run --project API
   dotnet run --project View
   ```

5. פתחו `http://localhost:5012`, צרו חשבון תלמיד והתחברו. ה־API נמצא ב־`http://localhost:5214`.

אין סיסמת ברירת מחדל. משתמשי הדגמה כבויים כברירת מחדל. רק לפיתוח ובסיס נתונים ריק אפשר להגדיר
`Seed:Enabled=true` ו־`Seed:DemoPassword` (8–72 בתים ב־UTF-8). ב־Production לא נוצרים משתמשי הדגמה.

## הגדרות

| מפתח | ברירת מחדל / תפקיד |
|---|---|
| `ConnectionStrings:DefaultConnection` | חובה; חיבור ל־MySQL ב־API |
| `OpenAI:ApiKey` | מפתח שרת בלבד; חובה לניתוח אמיתי |
| `OpenAI:TranscriptionModel` | `gpt-4o-mini-transcribe` |
| `OpenAI:FeedbackModel` | `gpt-4.1-mini` |
| `Practice:DailyLimit` | 5; המכסה מתחדשת ב־00:00 UTC |
| `Audio:Directory` | `API/App_Data/audio`; חייב להיות אחסון פרטי מתמשך |
| `ApiBaseUrl` | כתובת ה־API כפי שנגישה משרת View |
| `DataProtection:Directory` | `View/App_Data/keys`; מפתחות העוגיות, באחסון פרטי מתמשך |

משתני סביבה משתמשים ב־`__` במקום `:`, למשל `OpenAI__ApiKey`.

## בדיקות

```sh
dotnet build SpeakReady.sln
dotnet test tests/SpeakReady.Tests/SpeakReady.Tests.csproj
```

לפני בדיקות האינטגרציה הגדירו `SPEAKREADY_TEST_DB` לחיבור לשרת MySQL **נפרד וזמני**.
הבדיקות יוצרות בו את `SpeakReadyDB` וחשבונות בדיקה. אין להריץ מול נתוני משתמשים אמיתיים.
נדרש FFmpeg. שירות AI מוחלף בשירות בדיקה בתוך תהליך הבדיקות בלבד; אין קריאות בתשלום.
CI מפעיל MySQL זמני ובודק בנייה, הרשאות, הקלטה, עיבוד, כפילויות, מכסות, מחיקה וניסיונות חוזרים.

בדיקת דפדפן ידנית: הרשמה → כניסה → תרגיל → אישור מיקרופון → הקלטה → האזנה → הסכמה → שליחה → משוב.
בדקו גם רענון לאחר כניסה, התנתקות, סירוב למיקרופון, ניתוק רשת, מסך טלפון ומחיקת ניסיון.

## פריסה ופיילוט

הוראות HTTPS, Docker, גיבוי ושחזור ומדדי הפיילוט נמצאות ב־[docs/PILOT.md](docs/PILOT.md).
לא נפרס שירות ציבורי ולא נוצר חשבון בתשלום כחלק מהקוד.

מומלץ להתחיל ב־5–10 תלמידים, ולבקש ממורה לאנגלית לבדוק את איכות המשוב לפני הרחבת השימוש.
המשך הפיתוח: קבוצות ושיוך משימות, משוב מורה, ניהול תוכן והערכת דיבור ייעודית.

### בדיקת דפדפן אוטומטית

בסביבת בדיקה נפרדת, עם `SPEAKREADY_TEST_DB` מוגדר:

```sh
dotnet run --project tests/BrowserHost
dotnet run --project View
python tests/browser_smoke.py
```

מריצים את שתי הפקודות הראשונות במסופים נפרדים. הפקודה השלישית דורשת Python Playwright ו־Chromium;
אפשר להגדיר `CHROMIUM_PATH` למיקום הדפדפן. היא משתמשת במיקרופון מדומה ובשירות AI של בדיקות.
אין להפעיל את BrowserHost יחד עם בדיקות האינטגרציה או לפרוס אותו לציבור.
